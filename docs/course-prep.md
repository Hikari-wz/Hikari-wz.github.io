# 课程学习与备考中心

登录后，从「学业中心」打开「课程学习与备考中心」。首页按账号设置中的时区的周一至周日显示任务。选课名进入该课程的学习路线与资料。首页和学习路线共用任务，勾选、修改及删除会通过数据中心同步。

## 导入现有周任务

1. 在学业中心选择或建立对应学期，确认各科已经关联到该学期。
2. 从备考首页进入课程，在「学习路线」选择该课的 Markdown 周任务文件。
3. 核对来源课程、目的课程、任务内容和解析提示。选择 W1 对应的周一，预览后确认。其余相对周次顺延。原本的周次无需对应任何一天的学习安排。
4. 逐科导入。已存在的原始任务标识会被跳过，保留勾选状态、编辑及移动。若清单原文有修改，核对预览中的候选新条目再决定是否加入。
5. 大学生心理健康可保持空白。完整原稿、考情分析、真题等可以单独上传到课程资料。

## 数据和上线

- 新迁移扩展既有 `desk_entities` 的记录类型。每条任务单独记录学期、课程、周一日期、顺序、标题、说明、完成状态及可选导入标识。每项资料单独记录链接或文件元数据。两者继续使用 `desk_snapshot`、`desk_commit` 和数据中心的队列、冲突提示、删除墓碑与备份合并。
- 文件本体保存在私有 `desk-prep-files` bucket，路径为当前账号 UUID 和资料 UUID。单文件上限 25 MiB，Markdown 站内阅读上限 1 MiB。浏览或下载需要登录。课程计划、资料和备份请保存在自己的私有空间。
- 上线前将本 PR 新增的迁移应用到 Hikari’s Space 使用的 Supabase 项目。迁移会创建 bucket 和用户级访问策略。空项目按文件名顺序应用全部迁移；已有项目仅应用未登记的迁移。前端继续使用既有云端配置。上线后刷新此前打开的工作台和学业中心页面，以便旧页面更新到能识别新增记录类型的版本。
- 先在测试项目用两套独立账号检查文件访问和 RLS，再合并并部署前端。合并后从另一设备登录同一账号，复查同步和课程资料。

## 备份与恢复

数据中心的完整云端 JSON 包含任务、勾选状态、链接、文件元数据及删除墓碑。附件本体需在课程的「资料」中另行下载并保留。为便于补回，建议按学期和课程保存附件并保留原始文件名。仍在同一项目和账号、且对象仍存在时，恢复后的元数据可以继续打开原有文件。迁移到新项目或账号时，先恢复 JSON，再打开对应资料。资料提示文件缺失时，点击「补充缺失文件」，选择自己保留的原始文件。

导入的备份如果要求删除云端现有文件资料，合并时保留该资料。确实要删除时，从课程「资料」页操作，先清理文件本体再删除资料记录。
